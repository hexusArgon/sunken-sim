# Промпт 1. Получаемый урон + удаление Python-модели (13 классов на GPU)

Порядок работ (решение): сначала этот промпт целиком, потом промпт 2
(`docs/prompts/port-to-gpu-remaining-classes.md`). Классы запускаются по одному, не параллельно.
Приоритеты: сначала точность, потом скорость и оптимизация.

Классы: Berserker, Death Knight, Demon Hunter, Dragon Sentinel, Druid, Feral Druid, Hunter, Mage, Monk,
Necromancer, Paladin, Priest, Shaman. (Druid и Feral Druid — разные классы.)

Задача из двух частей: (А) отказаться от Python-модели боя у этих классов и удалить её, оставив только
GPU-ядра; (Б) добавить в GPU-ядра расчёт урона, который герой получает, и всех эффектов, через которые это
даёт прирост DPS.

## Контекст проекта (общий для обоих промптов)

- Репозиторий: https://github.com/hexusArgon/sunken-sim (ветки `main` и `cursor/run-from-map-39a3` держим одинаковыми).
  На ПК пользователя (Windows): `C:\Users\eseid\sunken-sim`, прогоны — `C:\Users\eseid\sunken-sim-runs`.
- Сим DPS героев карты Sunken City (WC3). Источник истины — скрипт карты 2.5.2c: `_hotfix/c_new/war3map_norm.j`
  (+ `war3map.w3t/.w3a/.w3u/.wts` там же). Для чтения триггеров: `tools/jass_inline.py`, `tools/jass_rules.py`.
- GPU: точные float64 OpenCL-ядра (`farm/hybrid/<класс>_cl.py`, общий движок `farm/hybrid/class_cl.py`
  (ExactCL), `character_tables`, `attack_procs_cl.py`, маршрутизация `farm/hybrid/opencl_route.py`,
  `farm/admission.py`, `tools/run_opencl.py`, `tools/opencl_check.py`, тесты `farm/hybrid/test_class_cl.py`).
  Правила точности: `FP_CONTRACT OFF`, суммы в порядке вставки (как `Ledger`), без fma, совпадение до бита.
  Сверку с Python запускать только на python3.11 (sum() в 3.13 компенсированный и даёт расхождения в ulp).
  В облаке есть pocl для OpenCL; на ПК — `.venv-dml` (Python 3.11) и реальная видеокарта.
- Поиск: топ-150 предметов по одиночному DPS → полный перебор 6 слотов, отбор «голых» сборок в топ-50,
  затем полный расчёт с талантами/глифами. Таблицы одиночного DPS: `extract/<hero>-one-slot.json`, `farm/top.py`.
- HTML: `docs/sim-html` (сборка: `tools/class_html_enrich.py`, `tools/class_page_tips.py`, `tools/sim_html_data.py`,
  `docs/sim-html/build/wc3col/apply.py`, `tools/sim_run_times.py`, `node build.mjs`, `node jt.mjs`, `build_index.py`).
- Модель входящего урона (решения пользователя, `docs/defense-model.md`, код `sunken_sim/pressure.py`):
  * каждый манекен бьёт героя на 5% его максимального HP раз в 1 с; манекены бьют по очереди с шагом 0.2 с
    (манекен j бьёт в 0.2·(j mod 5 + 1) + k секунд); герой лечится на 75% max HP каждые 3 с; HP не ниже 1;
  * round(N·122/176) манекенов — ближний бой (атака Normal), остальные — дальний бой (атака Magic);
  * все манекены стоят впритык к герою: дальники бьют с очень близкой дистанции. Признак «ближний бой»
    у карты берётся из типа оружия (UNIT_TYPE_MELEE_ATTACKER), а не из дистанции; дистанция важна только
    для радиусов (ауры, «ближайшие враги», AoE вокруг героя) — до всех манекенов радиусы достают;
  * снижение входящего урона (броня, тип атаки, % и фиксированные снижения, щиты) НЕ считается:
    удар = ровно 5% max HP. Временные снижения от своих способностей и предметов тоже не считаются;
  * уклонение СЧИТАЕТСЯ (шанс уклонения героя по правилам карты, PreDamage_Reduce) вместе с эффектами
    «при уклонении»;
  * манекены бьют только героя, питомцев/призванных игнорируют;
  * вампиризм, регенерация HP и лечащие эффекты не считаются, если не влияют на DPS; если влияют (например,
    через эффекты, зависящие от HP героя), их считать;
  * мана, получаемая при получении урона, учитывается.

## Часть А. Удаление Python-модели

1. Найди всех потребителей Python-симов этих классов (`sunken_sim/<класс>.py`, `farm/hybrid/<класс>.py`,
   `*_gpu_timeline.py`, enrich, таблицы одиночного DPS, подсказки HTML, тесты, инструменты в `tools/`) и
   составь список: что переводится на GPU, что удаляется. Покажи пользователю до удаления.
2. До удаления зафиксируй эталоны: для каждого спека, 5 и 1 цели, набор сборок (случайные + топ-20 из
   HTML), значения Python и GPU (они совпадают побитово) → `farm/hybrid/fixtures/`. Это регрессионные тесты
   ядер после удаления Python.
3. Переведи всех потребителей на GPU-ядра (одиночные таблицы, enrich, подсказки и т. д.), затем удали
   Python-модели этих 13 классов и тесты сверки Python↔GPU для них.
4. НЕ удаляй общий Python-код, который нужен классам Rogue, Siren, Tidewarrior, Tinker, Warlock, Warrior,
   Windmaster, Witch Doctor (library, ledger, attack_procs, pressure, search, их симы и т. п.) — их переносит
   на GPU отдельная сессия и Python там остаётся эталоном.
5. Проверка: эталоны из п. 2 совпадают до бита; HTML собирается; прогон одного спека проходит.

## Часть Б. Получаемый урон в GPU-ядрах

1. Инвентаризация по карте: для каждого спека проверь ВСЕ предметы его таблицы (их больше 320, не только
   топ-150), все таланты, глифы и способности. Выпиши эффекты, связанные с получением урона и уклонением:
   отражение в % от удара вблизи (Spiked Armor/Carapace, Thorns Aura, Dragonscale Aura, Volcanic Shield;
   ауры с одним названием не складываются), фиксированное отражение (Chaos Shard, Lightning Shield,
   Shield of Death), урон при получении удара (Sunstrider Crown, Axe Mastery, Blazing Shield у Dragon
   Sentinel, Demon Spikes), урон/эффекты при уклонении, баффы при получении удара (Berserk, Warlord's
   Battlemask, Seal of the Black Empire, Enraged Regeneration и т. п.), мана при получении удара, эффекты,
   зависящие от HP героя, и источники лечения для них. Для каждого эффекта — формула из скрипта, тип урона,
   шанс (с учётом Luck), перезарядка, что он может вызвать дальше (крит заклинаний, Sulfuras, проки от
   урона и т. п.). Результат — таблица в `docs/defense-model.md`. Сомнительные места — спросить пользователя.
2. Общий слой (его потом без изменений подключат 8 классов из промпта 2, проектируй под это): поток ударов (время, манекен, ближний/дальний), шанс уклонения героя по карте, HP героя
   (только если в сборке есть эффект, зависящий от HP; тогда с лечением, влияющим на DPS), мана.
   Таблица параметров эффектов → общий C-код, подключаемый во все ядра.
3. Получаемый урон не должен считаться, если в сборке нет ни одного эффекта, дающего от него прирост DPS:
   флаг по предметам/талантам/глифам/способностям, при нуле — старый быстрый путь ядра без изменений.
4. Подключи слой в ядро каждого класса: урон от отражения и ответных эффектов идёт через обычный расчёт
   урона класса (усилители, криты по правилам карты, дебаффы на цели); баффы — в ход боя.
   Порядок: Dragon Sentinel, Berserker, Demon Hunter, затем остальные.
5. Проверка без Python: юнит-тесты на формулы из скрипта (ручной расчёт на простых сборках), эталоны
   части А не меняются для сборок без таких эффектов, сравнение 5 и 1 цели. Замерь замедление ядра на
   сборках с эффектами и без.
6. Пересчитай таблицы одиночного DPS всех 13 классов (они задают топ-150 и список талантов), покажи
   пользователю, какие предметы/таланты вошли и выпали. Прогоны и HTML — после согласия пользователя.
