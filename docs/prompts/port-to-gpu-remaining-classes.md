# Промпт 2. Перенос на GPU, получаемый урон и удаление Python (8 классов)

Классы: Rogue, Siren, Tidewarrior, Tinker, Warlock, Warrior, Windmaster, Witch Doctor.

Запускать после завершения промпта 1 (`docs/prompts/incoming-damage-gpu-classes.md`): он делает общий слой
получаемого урона в GPU и удаляет Python у 13 классов. Классы делаются по одному, не параллельно.
Приоритеты: сначала точность, потом скорость и оптимизация.

Задача: на выходе эти 8 классов должны быть устроены так же, как 13 классов после промпта 1:
1. точное GPU-ядро, как у Berserker, Death Knight, Demon Hunter, Dragon Sentinel, Druid, Feral Druid,
   Hunter, Mage, Monk, Necromancer, Paladin, Priest, Shaman — Python-модель служит эталоном, пока ядро
   не совпадёт с ней до бита;
2. после этого — удаление Python-модели (как в части А промпта 1);
3. получаемый урон — через тот же общий слой, что в части Б промпта 1.

## Контекст проекта (общий для обоих промптов)

- Репозиторий: https://github.com/hexusArgon/sunken-sim (ветки `main` и `cursor/run-from-map-39a3` держим одинаковыми).
  На ПК пользователя (Windows): `C:\Users\eseid\sunken-sim`, прогоны — `C:\Users\eseid\sunken-sim-runs`.
- Сим DPS героев карты Sunken City (WC3). Источник истины — скрипт карты 2.5.2c: `_hotfix/c_new/war3map_norm.j`
  (+ `war3map.w3t/.w3a/.w3u/.wts` там же). Для чтения триггеров: `tools/jass_inline.py`, `tools/jass_rules.py`.
- GPU: точные float64 OpenCL-ядра (`farm/hybrid/<класс>_cl.py`, общий движок `farm/hybrid/class_cl.py`
  (ExactCL), `character_tables`, `attack_procs_cl.py`, маршрутизация `farm/hybrid/opencl_route.py`,
  `farm/admission.py`, `tools/run_opencl.py`, `tools/opencl_check.py`, тесты `farm/hybrid/test_class_cl.py`).
  Правила точности: `FP_CONTRACT OFF`, суммы в порядке вставки (как `Ledger`), без fma, совпадение до бита.
  Сверку с Python запускать только на python3.11 (sum() в 3.13 компенсированный и даёт расхождения в ulp).
  В облаке есть pocl для OpenCL; на ПК — `.venv-dml` (Python 3.11) и реальная видеокарта.
- Поиск: топ-150 предметов по одиночному DPS → полный перебор 6 слотов, отбор «голых» сборок в топ-50,
  затем полный расчёт с талантами/глифами. Таблицы одиночного DPS: `extract/<hero>-one-slot.json`, `farm/top.py`.
- HTML: `docs/sim-html` (сборка: `tools/class_html_enrich.py`, `tools/class_page_tips.py`, `tools/sim_html_data.py`,
  `docs/sim-html/build/wc3col/apply.py`, `tools/sim_run_times.py`, `node build.mjs`, `node jt.mjs`, `build_index.py`).
- Модель входящего урона (решения пользователя, `docs/defense-model.md`, код `sunken_sim/pressure.py`):
  * каждый манекен бьёт героя на 5% его максимального HP раз в 1 с; манекены бьют по очереди с шагом 0.2 с
    (манекен j бьёт в 0.2·(j mod 5 + 1) + k секунд); герой лечится на 75% max HP каждые 3 с; HP не ниже 1;
  * round(N·122/176) манекенов — ближний бой (атака Normal), остальные — дальний бой (атака Magic);
  * все манекены стоят впритык к герою: дальники бьют с очень близкой дистанции. Признак «ближний бой»
    у карты берётся из типа оружия (UNIT_TYPE_MELEE_ATTACKER), а не из дистанции; дистанция важна только
    для радиусов (ауры, «ближайшие враги», AoE вокруг героя) — до всех манекенов радиусы достают;
  * снижение входящего урона (броня, тип атаки, % и фиксированные снижения, щиты) НЕ считается:
    удар = ровно 5% max HP. Временные снижения от своих способностей и предметов тоже не считаются;
  * уклонение СЧИТАЕТСЯ (шанс уклонения героя по правилам карты, PreDamage_Reduce) вместе с эффектами
    «при уклонении»;
  * манекены бьют только героя, питомцев/призванных игнорируют;
  * вампиризм, регенерация HP и лечащие эффекты не считаются, если не влияют на DPS; если влияют (например,
    через эффекты, зависящие от HP героя), их считать;
  * мана, получаемая при получении урона, учитывается.
- Правила работы (обязательны):
  * Пиши пользователю по-русски.
  * При любом изменении коммить и пушь в обе ветки, не спрашивая. Автор коммита — как в последних коммитах
    (`git log -1 --format='%an <%ae>'`). Перед push делай fetch/rebase: параллельно может работать другая сессия.
  * Druid и Feral Druid — разные классы, не путать.
  * Discord-ботов не перезапускать.
  * Логику поиска (отбор, топы, гейты) менять только с согласия пользователя.
  * Оценки времени давать только по сопоставимым замерам.
  * Не захватывать экран, если пользователь в Dota или другом приложении.
  * Email пользователя приватный, никуда не передавать.
  * Git на примонтированной папке ПК не может удалять файлы: зависшие `.git/*.lock` переименовывай в
    `.git/stale-*`, удаление проси через device_request_delete_permission.


## Что сделать

1. Изучи готовые переносы как образец: `farm/hybrid/class_cl.py`, `monk_cl.py`, `necromancer_cl.py`,
   `berserker_cl.py`, `attack_procs_cl.py`, `character_tables`, маршрутизацию в `opencl_route.py`,
   `farm/admission.py`, `tools/run_opencl.py`, `tools/opencl_check.py`, `farm/hybrid/test_class_cl.py`.
2. Прежде чем писать ядро, проверь Python-сим класса против скрипта карты (формулы способностей, криты,
   Sulfuras, Luck, проки атак, глифы, таланты). Найденные ошибки исправь в Python и сообщи пользователю.
   Известное подозрение: у Warlock и Witch Doctor глиф Fortitude, возможно, добавляет STR, хотя у них
   основной атрибут INT — проверь по карте.
3. Для каждого класса и спека: ядро(а) в `farm/hybrid/<класс>_cl.py`, подключение к маршрутизации,
   admission и инструментам. Рекурсию (удар → пассивка → удар) разворачивать в копии без пассивки, как в
   готовых ядрах.
4. Сверка: python3.11, все спеки, 5 и 1 цели, случайные сборки с покрытием каждого предмета, полный
   расчёт с талантами/глифами — 0 расхождений до бита.
5. Замерь скорость ядра и сообщи; оценки времени прогона — только по замерам.
6. Удаление Python (по шагам части А промпта 1): эталоны Python/GPU в `farm/hybrid/fixtures/` для всех
   спеков, 5 и 1 цели; перевод всех потребителей на GPU; удаление Python-симов этих классов и тестов сверки;
   затем удаление общего Python-кода, который больше никому не нужен (library, ledger, attack_procs,
   pressure, search и т. п. — только если их уже ничто не использует, кроме удаляемого). Эталоны совпадают
   до бита, HTML собирается.
7. Получаемый урон: инвентаризация по карте для этих классов так же, как в части Б промпта 1 (ВСЕ предметы
   таблицы, таланты, глифы, способности; уклонение, мана, эффекты «при получении удара» и «при уклонении»,
   HP-зависимые эффекты и влияющее на DPS лечение) → дополнить таблицу в `docs/defense-model.md` →
   подключить общий слой в ядра; при отсутствии эффектов в сборке — быстрый путь ядра без изменений;
   юнит-тесты по формулам скрипта; замер скорости.
8. Пересчёт таблиц одиночного DPS этих классов; прогоны топ-150 и HTML — после согласия пользователя.
