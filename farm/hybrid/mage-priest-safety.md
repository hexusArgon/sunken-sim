# Mage Frost/Arcane + Priest Shadow/Discipline/Holy safety (t280)

## Confirmed applicable causes / changes
- Previously only Fire had a job-owned DML lease; these five specs could acquire one device per CPU worker. New DML worker cap: job-local `hybrid_dml_workers=1` (also the default). Other values fail explicitly pending per-spec hardware validation. This is conservative containment, not a claim that one is the measured optimum or all five have Fire's concurrency threshold. Fire's own explicit1..6/default1 remains unchanged; other classes are outside this patch.
- Parent preflight previously kept its device alive during the pool. These specs now use a spawned preflight which must exit before pool start, passing plain metadata only. Denied workers fall back before detection. Preflight failure retains honest CPU fallback; Arcane's existing default GPU eligibility and `FARM_HYBRID_ARCANE_GPU=0` CPU lock are preserved.
- Algebra may return a projected score; ordinary batched f32 scores also need not equal canonical final DPS. Re-score only the selected ESC build with the existing farm final-score oracle (Mage simulate; Priest compile_events/score_compiled, exactly as farm.score._priest—not plain simulate which differs by ulps), for batched/algebra and single/cross-build returns. Do not change selected talents/glyphs/points, search staging, strict tie ordering or reported logical fight formula. CPU final-score verification is separately counted; it is not hidden CPU compile fallback. This does NOT prove all hardware near-tie decisions for these specs; hardware winner parity remains required.
- Add per-PID execution/lease/GPUcompile/CPUcompile/canonical-final metadata. Priest previously had no compile counters; Frost/Arcane CPU-backed tests must not label CPU compile rows GPU. Observer/callback/log failures are contained, not added to numerical errors. A recovered observer write alone does not invalidate a trial; contaminated completions/errors/timing do.

## Machine ownership and active Fire
This is a per-job cap, NOT a machine-wide scheduler. One-job preflight and pool do not overlap, but other jobs/probes may still add GPU owners. Do not launch these jobs alongside the active six-owner Fire farm on this adapter. Do not derive a universal6-worker setting from Fire's result. Machine-wide arbitration is deferred, not implemented implicitly.

The active Fire job retains its resident imported code, recorded c904359 source fingerprint and checkpoint metadata. Common worker initializer signature/payload, Fire lease6, Fire math/search and checkpoint/signature functions remain compatible; no Fire restart, pause, checkpoint migration or metadata rewrite is part of t280. New checkout sources necessarily produce a NEW fingerprint for future jobs; never substitute it into the existing running job or bypass guards. A future resume after stopping Fire needs a separate fresh checkpoint/source reconciliation, not the historical one-shot helper.

## Measurement

No full farms, service/bot restarts, push or shutdown. Correctness/containment fixes make no speedup/ETA claim without a matched production benchmark.
